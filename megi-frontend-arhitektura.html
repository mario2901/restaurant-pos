Što sad ne radi ili fali nađeno u kodu

Glavni tokovi

Stol: prva narudžba → dodaj još → račun

  1. Tables: slobodan stol → Menu (bez orderId)
  2. Picker / Drinks / Addons → OrderContext
  3. Cart „Naruči“ → POST /orders/submit → TicketPreview (KITCHEN + BAR)
  4. Klik na zauzet stol → OrderDetails → „Dodaj još“ → Menu s orderId → opet submit
  5. „Račun“ → POST /orders/{id}/bill → TicketPreview (BILL), stol slobodan

Dostava i za ponijeti

  1. Klik na DOSTAVA → MultiOrderPicker (GET /orders/table/DOSTAVA/active)
  2. „Nova dostava“ → Menu bez orderId → submit otvara novu
  3. Postojeća dostava → OrderDetails → „Dodaj još“ (submit s orderId) ili „Račun“ u šanku
  4. PONIJETI isto, ali ostaje DINE_IN; kuhinjski tiket nosi „ZA PONIJETI“

Ispravke na narudžbi

  1. NEW stavka: stepper PATCH …/quantity ili DELETE …/items/{itemId}
  2. SENT stavka: „Storno“ POST …/items/{itemId}/cancel (ostaje zapisana, ne ulazi u iznos)
  3. Cijela narudžba: „Otkaži“ POST /orders/{id}/cancel vraća zalihu pića
  4. Printer zaglavio: ReprintMenu, GET kuhinja / šank / račun

TicketPreview prikazuje backendov Ticket 1:1

{ type, orderId, table, waiter, printedAt, lines[{quantity,name,detail,lineTotal}], total, takeaway, notice }. total i lineTotal su null na KITCHEN tiketu. notice ide istaknuto na vrh.

Dok printer (80 mm termalni) ne stigne, komponenta samo prikazuje tiket na ekranu. Kasnije se ovdje priključi ESC/POS ispis, bez diranja ostatka aplikacije.
